# 查重报告解读

## 判重规则

证据评估给出综合相似度后，脚本按下表判定（与原工作流一致）：

| 新项目条目类型 | 判为重复的条件 |
|---|---|
| 需求内容 | 相似度 ≥ 60 |
| 项目目标、项目成果 | 相似度 ≥ 70 |
| 项目内容 | 相似度 ≥ 60 |
| 新增功能（功能清单中状态为“新增”） | 相似度 ≥ 70 |
| 非新增功能 | 不算重复；相似度 > 70 时列入“重点标注” |

只要有一条判为重复，查重结论就是“重复”。只有项目名称同时含“设计开发”和“项目”时，才会把功能清单纳入查重。

## 报告结构

`report.md` 分为：

1. **[查重结论]**：重复 / 不重复。
2. **[重复项目名称]**：按最高相似度、重复证据数排序的历史项目。
3. **[全量重复明细]**：所有相关证据，包括未达阈值的条目，“是否重复”一列为判定结果。
4. **[项目需求重复点]**：需求内容、项目目标、项目成果中判为重复的条目。
5. **[项目内容重复点]**：项目内容和新增功能中判为重复的条目；有重复功能时另附“重复功能清单”，有高相似非新增功能时附“重点标注”。

## 向用户汇报

- 先说结论和主要重复的历史项目（项目名、重复条数、最高相似度）。
- 再挑 2~3 条最典型的重复点：新项目原文、历史项目片段、相似度。
- 状态里有警告（例如没有识别到需求或内容章节）时要明确告诉用户结论不可靠。
- 用户追问某条判定时，在 `evidence.json` 的 `all_evidence` 里找到该条，结合 `reason` 和 `evaluate/batch_*.input.md` 中的原始片段解释。

## 中间文件

| 文件 | 内容 |
|---|---|
| `text.md` | 文档提取出的全文 |
| `chunking.json` | 章节分块、功能清单 |
| `merge.json` | 合并后的需求、项目内容、功能清单 |
| `tasks.json` | 检索任务（`xmxq` 需求，`xmnr` 内容和功能） |
| `retrieval/hits.json` | 每条任务的知识库命中 |
| `candidates.json` | 评估批次 |
| `evidence.json` | 评估结果和历史项目排名 |
