# 项目查重

查重由内网查重服务上的「项目查重」工作流完成。信息提取、知识库检索、证据评估和重复判定都在工作流里，随包脚本负责上传文档、运行工作流和保存报告，你负责调用脚本和汇报结论。不要用网页搜索、本地文件或自己的知识代替工作流，也不要在本地自己提取、检索或打分。

查重比的是项目的业务需求和建设内容，不是通用的文字重复率检测。

下文 `SKILL` 指本文件所在目录。脚本只依赖 Python 3.9+ 标准库。

## 配置

脚本读取 `SKILL/config/service.json` 里的查重服务地址（`api_base`）和 API 密钥（`api_key`）。环境变量 `DEDUP_API_BASE`、`DEDUP_API_KEY` 优先，本地测试时可以用它们指向另一套服务，不用改配置文件。

`service.json` 含密钥，不进代码仓库。首次使用时把 `SKILL/config/service.example.json` 复制为 `service.json` 并填写密钥，或只设置环境变量。

## 执行

```bash
python3 SKILL/scripts/run.py <docx 文档或文件夹> [--output <报告目录>] [--overwrite] [--retry-failed]
```

一篇文档查重往往要十几分钟，超过单次命令的时间限制，所以脚本每次最多运行约 4 分钟（`--budget`，默认 240 秒）就退出，进度记在报告目录的 `.dedup-state.json` 里，工作流在查重服务上继续运行。**脚本输出最后一行以"未完成"开头（退出码 2）时，用完全相同的命令再运行一次，一直重复到不再出现"未完成"为止。** 这期间不要汇报结论，不要改参数，也不要删报告目录里的文件。重复运行不会重复提交：已经提交的文档只查询结果，查完的文档直接跳过。

运行方式：

- **在前台运行，等它自己结束。** 每次运行要么全部完成，要么约 4 分钟后自己退出，中途长时间没有输出是正常的。执行工具的超时参数和"转入后台前的等待时长"参数（例如 `timeoutSeconds`、`yieldMs`）都设为至少 300 秒（300000 毫秒），让一次调用就能拿到完整输出；不要主动把命令放到后台。
- 一次运行结束后，看它输出的最后一行再决定下一步。不要用 `ps`、查看状态文件等方式中途检查，不要在它结束前再启动一个 `run.py`（同一报告目录同时只能有一个在运行，多启动的会被拒绝），也不要用 `| tail`、`| head` 截断输出。
- 执行工具如果还是把命令转到了后台，就用它提供的带超时的等待方式（例如 `process` 的 `poll` 加 `timeout`，每次等 60 秒以上）等这个任务结束，再读取完整输出；不要用不等待的查看方式隔几秒查一次。
- 查重全部完成之前不要结束这一轮回复：不要发"还在跑"之类的进展，也不要问用户要不要继续，直接接着运行。

- 只支持 docx。遇到 doc、wps 等格式时，请用户先用 Word/WPS 另存为 docx。原始文档不改动。
- 给文件夹时递归查找其中的 docx，按顺序逐篇上传、运行工作流。报告按相对目录保存，例如 `a/b/项目.docx` 的报告写到 `<报告目录>/a/b/项目.md`。
- 报告目录默认是 `./dedup-reports`。已有同名报告时脚本会跳过，先问用户是否覆盖，同意后再加 `--overwrite`。文档内容改过的会自动重新查重。
- 进度打印在 stderr（上传进度、运行时长）。
- `--budget 0` 表示一直运行到全部完成，只在用户明确要求时使用（适合确认支持长时间命令的环境）；它和默认方式共用进度，中断后用默认命令即可继续。

stdout 先打印 JSON，`results` 里是每篇文档的状态：`succeeded`（附报告路径）、`failed`（附错误原因）、`skipped`（报告已存在）、`running`（工作流运行中）或 `pending`（等待上传）；最后一行是给你的提示。退出码：0 全部成功，1 全部结束但有失败或跳过，2 还没结束需要再运行。

报告正文是工作流结束节点的输出，脚本原样保存，不做改写。

## 失败处理

- 提示"查重服务不可用"（缺少配置、连不上服务、密钥错误）时，把错误原文告诉用户并停下。
- 某一篇失败时，脚本会继续处理下一篇。失败就是"查重未完成"，绝不能当成"不重复"。`running`、`pending` 也是查重未完成。
- 失败的文档不会自动重跑。把原因告诉用户，用户要求重试时加 `--retry-failed` 运行，同样重复到不再出现"未完成"。
- 上传超时说明网络太慢，一次命令内传不完，重试也一样。告诉用户可以压缩文档里的图片，或在支持长时间命令的环境里加 `--budget 0` 运行。
- 提示"上一次运行还没结束"时，说明之前启动的 `run.py` 还在运行，等它结束后再用同一命令运行，不要删锁文件。
