# 项目查重

查重由内网查重服务上的「项目查重」工作流完成。信息提取、知识库检索、证据评估和重复判定都在工作流里，随包脚本负责上传文档、运行工作流和保存报告，你负责调用脚本和汇报结论。不要用网页搜索、本地文件或自己的知识代替工作流，也不要在本地自己提取、检索或打分。

查重比的是项目的业务需求和建设内容，不是通用的文字重复率检测。

下文 `SKILL` 指本文件所在目录。脚本只依赖 Python 3.9+ 标准库。

## 配置

脚本读取 `SKILL/config/service.json` 里的查重服务地址（`api_base`）和 API 密钥（`api_key`）。环境变量 `DEDUP_API_BASE`、`DEDUP_API_KEY` 优先，本地测试时可以用它们指向另一套服务，不用改配置文件。

`service.json` 含密钥，不进代码仓库。首次使用时把 `SKILL/config/service.example.json` 复制为 `service.json` 并填写密钥，或只设置环境变量。

## 执行

```bash
python3 SKILL/scripts/run.py <docx 文档或文件夹> [--output <报告目录>] [--overwrite]
```

- 只支持 docx。遇到 doc、wps 等格式时，请用户先用 Word/WPS 另存为 docx。原始文档不改动。
- 给文件夹时递归查找其中的 docx，每篇单独上传、单独运行一次工作流。报告按相对目录保存，例如 `a/b/项目.docx` 的报告写到 `<报告目录>/a/b/项目.md`。
- 报告目录默认是 `./dedup-reports`。已有同名报告时脚本会跳过，先问用户是否覆盖，同意后再加 `--overwrite` 重跑。
- 工作流要跑完提取、检索和评估，耗时可能较长。脚本用流式模式等待结果，进度打印在 stderr，耐心等它结束。

脚本结束时在 stdout 打印每篇文档的结果：`status` 为 `succeeded`（附报告路径）、`failed`（附错误原因）或 `skipped`（报告已存在）。全部成功时退出码为 0，否则为 1。

报告正文是工作流结束节点的输出，脚本原样保存，不做改写。

## 失败处理

- 缺少配置、连不上查重服务、密钥错误（HTTP 401）时，把错误原文告诉用户并停下。
- 某一篇失败时，脚本会继续处理下一篇。失败就是"查重未完成"，绝不能当成"不重复"。
- 断流、超时或"没有收到工作流完成事件"时，不要立即重新运行同一份文档，因为原任务可能还在服务端运行，应先请用户到查重服务查看运行日志。
